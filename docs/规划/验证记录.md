# 验证记录

本文汇总 isbench 的跨环境验证判定基准与关键结论。测物 = 交付物：同一份 `dist`
推到各目标机，目标机上一律不重编（现场重编会因参数与自检脚本漂移，得出只在本机
成立的结论）。

## 双基准判定

- **判定基准只有两条**：在 x86_64 参考机上跑的 native ELF，与在 Windows 本机直跑的 PE。
  两者结果一致（T 行数 / katOK / KATFAIL 逐项同数）=> 测试工具与被测代码都没问题。
  LATX 或 wine 报出的差异属另一层（翻译器 / wine 自身），应在那边修，**不得倒逼改
  测试工具的判据** —— 工具要保持干净：数据通道只承载探针 stdout，解析判据不因外部
  噪声放宽。
- **PE 判定优先 Windows 本机直跑**（wine 可能不正确）：PE 侧结果与 native 逐项同数即
  产物无问题。取原始输出时须注意平台差异（例如某些 shell 重定向会改编码，导致解析
  整份判 0 行）。

## 构建可复现性

- 重跑构建后逐文件哈希对账（按路径 join，只比共同文件，避免把"目标机没推的新产物"
  误读成"产物变了"）：通常仅 `windows.exe` 与个别文档变化 —— `*_linux` 与 `.a` 不变，
  即指令探针 ELF 逐文件未变。
- **PE 属不可复现构建**：mingw 在 PE 头写 `TimeDateStamp`（构建时刻），源码没变哈希也会变。
  所以只要重跑过构建，Windows 本机 PE 基准必须重跑一次，才能说"双基准对同一份 dist 成立"。
- 本地 dist 可能含目标机未推的 openssl 探针产物（不属指令矩阵），要跑 openssl 需单独推送。

## 各环境结论

- **native（x86_64 参考机）**：`run native --time 300` -> 全组指令行，katOK / KATFAIL=0 /
  COLLECT=0 / CRASH=0。i386 行数天然少（mov 16/34、alu 15/31、ctrl 2/8）是能力门控
  （.q/REX.W 形态只在 64 位注册），不是失败。
- **Windows PE（本机直跑）**：32 个 PE -> T / katOK / KATFAIL / KATPEND / CRASH / PEND
  与 native 逐项同数 -> PE 侧产物无问题。
- **wine**：需将 stdout 与 stderr 分管道捕获 —— 噪声（wine 启动警告、GL/MESA 警告）全在
  stderr，数据通道（stdout）首行即 kind 表头。把 stderr 缩成一行只进 notes 诊断列，并保持
  `parse_seg`「表头必须在第 1 行」的严格判据（不因外部噪声放宽）。
- **LATX（翻译机）**：`run latx` 行数与 native 同数；与 native 对拍功能类例外可分两类：
  - HOSTUNSUPPORTED = 翻译器能力边界（参考机硬件有该能力但翻译器不发射），记档；
  - KATFAIL = 已定到指令级（如某位标志未按架构清零），修复方向在翻译器侧。
  计时只作开销数据；个别算法存在跨 run 计时不稳，属计时侧。

## 判据沿革（为什么）

- **亚 ns 行不参与跨 run 自校验**（`CHECK_MIN_NS = 1.0`）：同机多轮 native 的亚 ns 行
  （如 0.30/0.45/0.31 ns）在计时粒度上天然抖动，会连报 >±10% MISMATCH；同组 i386 行与
  计时量级较大的行则全稳定 —— 不是内核不确定，是这一行本身在计时粒度上。现显示
  `consistent(亚ns跳过N)`。
- **防折叠检查须每配置跑 2 次取 best**（噪声只会把时间读长），同 iters 比 sig、跨 iters
  只比量级 —— `lat_sig` 本就随 iters 变（`s = c->lat(it)`），拿它跨 iters 比是错判据；
  一次调度抢占就能把 ns 级读数放大到数十倍（假例外）。
- 计时签名退化（真机部分行 `tput_sig` 恒 0）按现行口径只记档不返工：只影响计时列
  区分度，正确性由 KAT 逐字段比对承担（见 [../设计/功能测试与KAT.md](../设计/功能测试与KAT.md)）。
