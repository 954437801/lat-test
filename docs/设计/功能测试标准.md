# isbench 功能测试标准（KAT v2）

本文件是 isbench 指令测试工具**功能测试**的单一标准出处。性能测试（latency/throughput/
block8）与本文档无关；本文只管"这条指令译对没有"。

## 1. 测试对象与真值来源

- 测试对象：LATX 用户态 x86 → LoongArch 翻译器。功能测试 = 同一条 x86 指令经翻译执行
  后，其输出（寄存器 / 内存 / 标志）与**真 x86 语义**逐位一致。
- 真值来源：只能来自**真 x86 硬件**。本地 WSL（x86_64 ELF）与 Windows 本机（PE）都是真
  x86，采集**全程本地完成，不依赖任何外部机器**。
- 禁止在翻译层（LATX / box22）上采集真值：那里的执行结果是翻译器产物，把它当"真值"
  等于让被测者自己出题。采集端由守卫（§5）拦下。

## 2. 统一真值单元（`src/ib_core.h` 的 `ib_kv`）

```c
typedef struct {
    uint64_t i0, i1, i2, i3;   /* 输入 4 字 = 最多 256 位 */
    uint64_t inf;              /* 入标志(IB_KFL 掩码后值) */
    uint64_t o0, o1, o2, o3;   /* 输出 4 字 */
    uint64_t outf;             /* 出标志 */
} ib_kv;
```

- 覆盖宽度：GPR 32/64、XMM 128、YMM 256、x87 80 位、EFLAGS。
  这样 avx 的 ymm 结果能逐字比对（旧单元只有 `o0/o1` 两个 64 位槽，装不下 256 位，
  是 avx/vec 早先只能靠语义签名、判不出"对不对"的结构性根因）。
- **判定口径**：只比输出 `o0..o3 + outf`（`IB_KV_OUT_OFF=5, IB_KV_OUT_N=5`）。
  输入存表仅用于**错档核**，不参与判定（输入本就由生成器确定性推出，比它等于自己跟
  自己比）。
- 结构序固定：改动字段序 = 全仓真值表作废、必须重采。
- 每个用例固定 `IB_KAT_N = 8` 个真值槽 `kexp[8]`；`IB_KV_UNSET` 是"未回填"哨兵壳
  （输出 4 字全 `IB_KV_MAGIC`）。

## 3. 统一输入生成器（`src/ib_gen.h`）

一个功能测试点的输入必须满足两条：

1. 确定性：同 `(片段名, 槽号 k, 字槽 slot)` 在任何机器、任何语言重写都得同一个值
   —— 编译期可重算、不依赖数据文件、不依赖浮点/随机源；
2. 可复现：采集机与被测机各自现场重算，不靠"把输入也存进表"来对齐。

两类来源：

- `IB_G(sn, k, slot)`：哈希派生（`ib_strhash(片段名)` + `k` + `slot` 经 `ib_kin` 混合），
  用于通用 GPR / SIMD / 内存地址。`IB_KIN` / `IB_KIN8` 是它的兼容别名，**不是第二套实现**。
- `IB_GB(sn, k, idx)`：边界向量表 `ib_gb_vec[]`（0 / 1 / 全 1 / INT64_MAX / INT64_MIN /
  2^53 / 2^53+1 / 0xaa 填充 / 0x55 填充 / 低位全 1 / 高位稠密），用于需要"恰好在缺陷
  分界线上"的族（哈希推不出这些值）。
- `IB_KFL(sn, k)`：入标志，恒置 bit1（RES 位）并按族套掩码，只比可比对的状态位。

各 .c 里的 `IB_ROW_K`（`src/ib_buf.h`）把用例、内核、真值表、词干声明式地串起来。

## 4. 判定与状态机（`src/ib_core.h`）

- 编译期真值表：每个词干一份 `IB_KAT_<stem>`（8 槽 × 10 字），生成物，请勿手改。
- 运行时：`ib_case_kat` 逐槽跑内核取 `got`：先做**错档核**（表内输入 `i0..i3+inf`
  必须 == 现场生成输入, 否则该 case 判 `INMISMATCH`), 再与表内输出 5 字 `memcmp`。
- 状态串（`ib_fields.h`）：
  - `OK` / `PASS` → 功能 **true**
  - `FAIL` / `KATFAIL` / `CRASH` / `INMISMATCH`（错档核不过）→ 功能 **false**
  - `COLLECT`（表未回填）/ `NOGOLD` / `HOSTUNSUPPORTED` → 功能 **-**
- 功能结果由 `ib_func_verdict()` 映射，经 `func` 段落 `verify_<grp>` 表（一行一用例，
  列 = 各功能，值 true/false/-）。详细 in/gold/got 明细由 `--debug` 时的 `dbg` 段落
  `debug_<grp>` 表。

## 5. 采集与守卫（脚本合并 + 编译时采集）

- 采集 = "测试前备好确定性输入 → 跑完指令 → 把输出存成常量表"，由 `pack/gen_val.sh`
  （合并原 `_tmp/gen_kat.sh` 与 `pack/gen_gold_pmul.sh`）统一驱动，步骤：
  形状自检 / 幂等复跑比对 sha256 / LF 校验 / 备份回填 / 复编闭环冒烟。
- **编译时采集**：构建机是真 x86_64，可在 `bash build/build.sh` 的 `make all` 之前插入采集阶段：
  编"采集版"探针 → 跑 `--gen-gold` 自出真值表 → 再编全部形态。`GEN=1 bash build/build.sh` 开启；
  默认构建沿用已入库真值表（表在库才可复现构建）。
- **必须的守卫**：
  - 采集机机器名必须 `x86_64`（`ib_gold_host_ok()`，排除 LATX）；Windows PE 侧沿用
    "PE 只在真 x86 Windows 上跑"的约定；
  - 采集前核 CPUID 能力（pclmul / aes / sha / avx 等）；
  - 生成物形状自检 + 幂等（同机重跑 sha256 一致）+ LF 校验；校验不过保留旧表、不回退。
- **例外**：`x87` 只在 i386 在册，WSL 无 ia32 跑不了 i386 ELF → 其采集落在 **Windows
  本机直跑 i386 PE**，不依赖 box31 等外部机器。
- **例外（非硬件真值）**：`sfloat` 组的 f128 真值来自 GCC `__float128`（libgcc soft-fp，
  与 SoftFloat 相互独立的第二软实现）而非 x86 硬件 —— x86 无 128 位硬件。这是全仓唯一
  “非硬件真值”，已在 `src/sfloat/isb_sfloat_kat.h` 表头与 README 标注；f64/f80 仍为真硬件
  （SSE double / x87 long double，逐位）。采集由 `pack/gen_gold_sfloat.sh` 在真 x86_64 完成。

## 6. 分组清单与去重口径

### 6.1 各组的职责边界与接 KAT 现状

| 组 | 职责 | 功能测试现状 |
|---|---|---|
| scalar | 标量整数基线（add/mul 参考下限）+ crc32 | 已接 KAT（3 词干） |
| bits | 位测试 / 位扫描 / 位操纵（bt/bts/bsf/bsr/popcnt/lzcnt/tzcnt + BMI1/BMI2） | 已接 KAT |
| alu | 算术指令族（add/sub/inc/dec/neg/sbb/adc/imul/idiv/mul/div） | 已接 KAT |
| logic | 逻辑指令（and/or/xor/not） | 已接 KAT |
| flag | 标志位（cmp/test） | 已接 KAT |
| shift | 移位/旋转（shr/shl/sar/rol/ror/shld/shrd/SHLX/SARX/SHRX/RORX） | 已接 KAT |
| cc | 条件码（jcc/setcc/cmovcc） | 已接 KAT |
| ctrl | 栈与控制转移（push/pop/leave/retf/pushf） | 已接 KAT |
| mov | 数据搬运（mov/movzx/movsx/bswap/cwtl/cltq/cqto/movbe） | 已接 KAT |
| special | 原子 / 串 / 屏障（xchg/cmpxchg/xadd/串操作/fence/pause/prefetch/nop） | 部分（有架构结果的接 KAT，纯开销的不接） |
| vec | 整数 lane 数据操作 + 浮点↔整数转换 | 已接 KAT（avx* 已迁出，见 §6.3） |
| sse | SSE..SSE4.x 访存 + 浮点/整数算术 | 已接 KAT（42 词干，含 5 条 sem 转 KAT） |
| avx | 全部 VEX 编码（含 128/256） | 已接 KAT（22 词干，含 vec 迁入 7 条与 256 位） |
| crypto | AES-NI / PCLMULQDQ / SHA 单指令 | 已接 KAT（4 词干 + 3 条独立 AES KAT） |
| x87 | x87 浮点/整型搬运与状态字（P1-P7） | 已接 KAT（47 词干，i386 PE 采集） |
| cpuid / timer | 环境探测（能力清单 / 时钟） | 不接 KAT，走 diag 判定 |
| pmul | 同一条 64x64→128 无进位乘的多实现对照 | 自有 96 档 gold（见 §7） |
| sfloat | 软浮点(SoftFloat-3e) f64/f80/f128 三宽度原语延迟 | 已接 KAT（15 词干，8 槽/词干；sin 两条仅测速不接） |

### 6.2 cross 组重复：已判定的去重

- **popcnt / lzcnt / bsf / bsr**：原 `scalar` 与 `bits` 两组都测 → **归 `bits`**
  （位扫描/位测试本就是 bits 的定位），已从 `scalar` 删除。
- **crypto 的 `aes_ecb128`**：与 openssl 探针的 `aes-128-ecb` 观测面重叠，且 openssl 是真实库
  实现 → **已删除**，库级 ECB 归 openssl；crypto 只留"单指令"延迟/吞吐。
- **pclmulqdq**：`crypto`（单指令快慢）与 `pmul`（多实现对照）各留一层，不合并。
- **crypto vs openssl**：不是重复 —— openssl 是**库级**（EVP 接口，真 OpenSSL 实现多快），
  crypto 是**指令级**（单条指令多快、译对没有）。两层各留。
- 同族不同宽度（paddq/paddw/paddd、psrlw/vpsrlw、pmulld/vpmulld）不算重复。

### 6.3 分组错位：已重组

- `vec` 曾混入 AVX/AVX2 指令（`avx_vmovdqu` / `avx_vptest` / `avx_vinsertf128` /
  `avx2_vpsllq` / `avx2_vpsrlq` / `avx2_vpsrlw` / `avx2_vpaddq`）→ **已移入 `avx`**
  （vec 由 36 用例降至 29）。
- `vec` 与 `sse` 边界模糊（两组都含 `sse2_*` / `sse41_*`）。重组口径：
  `sse` = 访存 + 浮点/整数算术；`vec` = 整数 lane 数据操作 + 浮点↔整数转换；
  `avx` = 全部 VEX 编码（含 128/256）。
- `scalar` 的 `sse42_crc32` 严格按 ISA 属 SSE4.2，保留在 scalar 作"标量兼用"参照。

## 7. pmul 的 gold 与通用 KAT 的关系

- 通用 KAT：真值来自 x86 参考机**采集**（探针在采集态把 `got` 打成 K 行，脚本收割成
  `isb_<grp>_kat.h`），判定 = 输出 5 字全等。
- pmul gold：96 档的输入由 `pmul_bits(L,k)` **公式**生成、输出由真机**硬件 pclmulqdq
  直算**采集（`--gen-gold`），判定 = 实测 limb 与采集值全等，并带"错档判 TIERMISMATCH"、
  "积不得溢出 128 位"、"采集机必须是真 x86_64" 三重守卫。
- 两者本质相同（输入确定性 + 输出真值比对），pmul 因为要覆盖 64x64→128 全宽 + 多实现
  对照，装不进 `ib_kv` 的 6/10 字模型，故自带一套；KAT v2 后其状态串与守卫与通用组对齐。

## 8. 单组 `--help` 契约

每个 `dist/bin/<grp>-<abi>_<os>` 的 `--help` / `-h` 由 `ib_core.h` 的 `ib_usage()` 生成
（pmul 用自己的 `pmul_usage()`），至少要说清：

- 用法行；
- 选项表（`--time` / `--iters` / `--only` / `--list` / `--debug` / `--no-lat` /
  `--no-tput` / `--no-b8` / `--no-sem` / `--help`），逐条给默认值与作用；
- 环境变量（`ISB_DEBUG` / `ISB_VERIFY`）；
- 输出协议（`meta` / `field` / `label` / `data` / `func` / `dbg` / `group`）；
- 功能判定口径（true/false/- 的来源）；
- 采集与守卫一句话。

`--list` 列出本组全部用例（名字 + 能力门控），不跑测试，便于拼 `--only`。

## 9. 落地状态（滚动更新）

- 真值单元 / 生成器 / 判定框架：10 槽 `ib_kv` + 输出-only 判定 + **错档核**
  （表内输入 != 现场生成输入 → `INMISMATCH`）；`ib_gen.h` 统一生成器；
  `ib_gold_host_ok()` 守卫；`ib_kline` / `dbg` 段 10 字。
- 去重 / 重组：`scalar` 去 popcnt/lzcnt/bsf/bsr；`crypto` 去 aes_ecb128；
  `vec` 的 7 条 avx* 迁入 `avx`。
- 接 KAT：scalar(3) / sse(42) / avx(22，含 vec 迁入 7) / vec(29 用例) / crypto(4) /
  x87(47 词干) 全部接真值表；两 ABI 共用一份 x86_64 采集表（x87 走 i386 PE）。
- 采集：`gen_val.sh` 合并统一（PE=1 走 i686 PE）；`bash build/build.sh GEN=1` 编译时采集阶段。
- 工具：`kat_audit.py`（独立第二实现，10 字段）+ `_tmp/kat_neg.sh`（15 处注入全检出）
  均已适配；全部已接表词干均经独立复算（15 组 / 341 词干，`不符=0 跳过=0`），不再有 SKIP。
- 验证：全矩阵构建 + 打包通过；x64_linux / i386_windows PE / x64_windows PE 三形态
  逐组零 KATFAIL / 零 INMISMATCH（ctrl 在 Linux 的 retf 为既知 CRASH，见 README）。
